## Какие сервисы подключены

Оба сервиса работают параллельно. Каждое событие уходит в оба, если подключены оба счётчика.

- **Яндекс.Метрика** — основной сервис для российской аудитории. Бесплатна, работает в России без обхода блокировок, данные хранятся в России (проще для 152-ФЗ). Даёт просмотры, цели, карту кликов и отчёт «Онлайн».
- **Google Analytics 4** — дополнительный сервис: воронки, сравнение периодов, привычные для команды отчёты.

Ограничения Google: его скрипт из России открывается нестабильно, а данные хранятся за пределами РФ. Поэтому GA стоит включать только если это согласовано с политикой обработки персональных данных. Без `VITE_GOOGLE_ANALYTICS_ID` он не подключается.

## Настройка

1. **Яндекс.Метрика.** Создать счётчик на metrika.yandex.ru, скопировать номер. Переменная: `VITE_YANDEX_METRIKA_ID=<номер>`.
2. **Google Analytics 4.** В Google Analytics: Администрирование → Потоки данных → Веб → добавить сайт. Скопировать «Идентификатор потока» вида `G-XXXXXXXXXX`. Переменная: `VITE_GOOGLE_ANALYTICS_ID=G-XXXXXXXXXX`.
3. Задать переменные:
   - локально: в `frontend/.env.local`;
   - продакшен: в Vercel → Settings → Environment Variables, затем новый деплой (переменные сборки подставляются только при сборке).
4. Для проверки в консоли при необходимости задать `VITE_ANALYTICS_DEBUG=true`. Тогда события печатаются как `[analytics] <имя> {...}`, даже без счётчиков.

Номера счётчиков не секретны, но в репозиторий их не коммитим: держим в переменных окружения.

## Каталог событий

Просмотры страниц отправляются автоматически при каждом переходе. В Google они идут событием `page_view`, в Метрике — как просмотр страницы.

| Событие | Где срабатывает | Параметры |
|---------|-----------------|-----------|
| `login_success` | Успешный вход (`auth.js`) | `role` |
| `login_failed` | Ошибка входа (`auth.js`) | `reason`: `invalid_credentials` или `error` |
| `register_success` | Успешная регистрация | — |
| `logout` | Кнопка «Выход» (`AppHeader.vue`) | — |
| `station_create` | Создание АЗС (`AzsListView.vue`) | — |
| `station_update` | Сохранение карточки АЗС (`AzsDetailView.vue`) | `station_id` |
| `analytics_tab_select` | Переключение вкладки аналитики | `tab` |
| `recommendations_generate` | Генерация рекомендаций (admin) | `saved`, `closed` |
| `recommendation_complete` | Отметка рекомендации выполненной | `priority` |
| `data_import_upload` | Успешная загрузка файлов импорта | `files_count` |

В Метрике события видны в отчёте «JavaScript-события». Для воронок и конверсий создайте цели с теми же идентификаторами (Настройки → Цели). В GA4 события появляются в разделе «События» и как пользовательские; для ключевых отметьте их как конверсии.

## Что не отправляется

- Логин, email, пароль, токен и телефон. Фильтр в `index.js` удаляет эти поля, даже если их передали по ошибке, и действует для обоих сервисов.
- Введённые данные: вебвизор (запись сессий) в Метрике отключён (`webvisor: false`), так как на экранах есть формы с паролями.
- Строки длиннее 100 символов обрезаются.

Оба сервиса сами собирают IP-адрес и cookie. Это персональные данные по 152-ФЗ, поэтому перед запуском нужно:

- указать использование аналитики в политике обработки персональных данных;
- решить, нужен ли баннер согласия на cookie (для внутреннего инструмента с входом по логину обычно достаточно уведомления в политике);
- решить, допустима ли передача данных в Google за пределы РФ.

Эти решения принимает владелец проекта, в коде они не закрыты.

## Проверка отправки

### Автоматические тесты

```bash
cd frontend && npx vitest run src/__tests__/analytics.test.js
```

Тесты проверяют: без номеров счётчиков ничего не подключается; оба скрипта подключаются один раз; просмотры и события уходят в оба сервиса с правильными параметрами; логин, пароль и токен не попадают в параметры; длинные строки обрезаются.

### Ручная проверка на реальных счётчиках

1. Запустить фронтенд с `VITE_YANDEX_METRIKA_ID`, `VITE_GOOGLE_ANALYTICS_ID` и `VITE_ANALYTICS_DEBUG=true`.
2. Открыть DevTools → Network. Фильтр `mc.yandex.ru`: должен загрузиться `tag.js`, затем запросы `watch/...`. Фильтр `google-analytics` или `collect`: должны идти запросы `g/collect` с `en=page_view` и событиями.
3. Открыть DevTools → Console. Выполнить вход, открыть страницы, выйти. Должны появиться строки `[analytics] login_success {role: ...}` и так далее.
4. В Метрике открыть отчёт «Онлайн» (или «Режим отладки»), в GA4 — «Отчёты в реальном времени». Просмотры и события должны появиться в течение минуты.
5. Проверить, что в запросах нет логина, пароля и токена.

Если запросы блокируются, в консоли будет ошибка CSP. Тогда нужно проверить заголовок `Content-Security-Policy` в `vercel.json`.
