# Инструкции для ИИ-агентов

Этот файл для агентов, которые работают с репозиторием АЗС-Пульт. Подробности — в [README.md](README.md) и `docs/`.

## Проект

- Backend: Express + TypeScript (`backend/`), PostgreSQL (Supabase) с RLS. Порт 3001.
- Frontend: Vue 3 + Vite + Pinia (`frontend/`). Порт 3000.
- Serverless для Vercel: `api/index.js` использует `backend/dist`. Конфигурация: `vercel.json`.
- Продакшен: https://otuswork5.vercel.app. Vercel деплоит ветку `main` репозитория `OTUS_work5`.

## Команды проверки

Перед коммитом запускайте проверки из CI:

```bash
cd backend && npm run format:check && npm run lint && npm run type-check && npm run test:unit && npm run build
cd frontend && npm run format:check && npm run lint && npx vitest run && npm run build
```

- Lint: 0 ошибок — норма. Предупреждения (95 в backend, 19 во frontend) — старый долг, не добавляйте новых.
- Форматирование: Prettier. Backend с точками с запятой, frontend без них (`frontend/.prettierrc.json`).
- Перед пушем проверяйте `git diff --cached` на пароли и ключи.

## Правила безопасности

- **Секреты не в чате и не в файлах.** Пароли, ключи, токены Vercel, UptimeRobot, Client Secret — только в переменных окружения пользователя или в настройках Vercel (тип Secret). Если пользователь прислал секрет в чат, предупредите, что его нужно перевыпустить.
- **Не выводите значения переменных окружения.** Проверяйте только факт наличия (`${VAR:+set}`), иначе значение попадёт в вывод.
- **`.env`, `.env.local`, `.vercel` в `.gitignore`.** Не коммитьте их.
- **Продакшен-база.** Только чтение без подтверждения. Любая запись, `drop`, `delete`, `alter`, смена паролей — только после явного подтверждения пользователя. Инструмент MCP может отклонить деструктивный запрос: повторно не отправляйте его в той же форме.
- **Пароли пользователей** (`admin`, `manager`, `analyst`, `viewer`, `manager1`) не подбирайте и не проверяйте без просьбы.
- **Пуш в `main`** запускает деплой в продакшен. Пушите в `main` только по явной просьбе пользователя и после проверки CI.

## Правила для кода

- **Роль БД.** Backend подключается под `azs_app` (без `BYPASSRLS`), RLS действует. Не добавляйте подключение под `postgres` в код приложения.
- **Новые таблицы.** Включайте RLS, задавайте политики и выдавайте права `azs_app` в миграции (см. `009`, `016`, `017`, `018`).
- **Новые маршруты `/api`.** По умолчанию получают контекст БД. Маршруты без базы добавляйте в `NO_DB_ROUTES` в `backend/src/middleware/db-context.middleware.ts`.
- **Доступ к станциям.** Через `accessibleStationIds` и `canAccessStation` (`backend/src/services/access.service.ts`). Роль `null` (деактивирован) — ничего не видит.
- **Роли.** Проверка через `requireRole` и `requireAdmin`. Роль берётся из таблицы `users`, не из токена.
- **Пароли пользователей.** bcrypt, 12 раундов. Политика: не короче 8 символов, заглавные и строчные буквы, цифра, спецсимвол.
- **Логи.** Не пишите пароли, токены, почту и тело запросов. Журналы — см. `docs/LOGGING.md`.
- **Ошибки БД клиенту не отдаём.** Детали — в журнал на сервере.

## Git

- Ветки для изменений создавайте от `main`. Коммиты — понятные сообщения на русском в формате `тип: описание` (`feat`, `fix`, `docs`, `security`, `perf`, `ci`, `style`).
- Не коммитьте служебные файлы ассистента без просьбы. Папки `.agents/`, `.claude/` и `skills-lock.json` уже в репозитории, обновляются только установкой навыков.
- Не переписывайте историю опубликованных веток (`git push --force` без просьбы).

## Инструменты и доступ

- **Vercel CLI** установлен глобально, папка привязана к проекту `otus_work5` (`.vercel/` в `.gitignore`). Вход: `vercel login` выполняет пользователь.
- **Supabase MCP** (`.mcp.json`) подключён к проекту `glnqdukqwapakhsuejcj`. Авторизация через OAuth в интерактивной сессии (`/mcp`). Запросы, меняющие данные или схему, — только после подтверждения.
- **UptimeRobot API:** ключ в переменной окружения `UPTIMEROBOT_API_KEY`. Не выводите его значение.
